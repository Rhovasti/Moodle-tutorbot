# Moodle Tutorbot - LTI Integration Setup Guide

This guide explains how to set up and deploy the Moodle Tutorbot as an LTI 1.3 tool that can be integrated into any Moodle instance.

## Architecture Overview

The application now consists of two parts:

1. **Backend (Node.js/Express)**: LTI provider, API endpoints, and Gemini AI integration
2. **Frontend (React/Vite)**: User interface served by the backend

```
┌──────────────────────┐
│  Moodle Instance     │
└──────────┬───────────┘
           │ LTI 1.3 Launch
           ↓
┌──────────────────────┐
│  Backend Server      │
│  - LTI Provider      │
│  - Session Management│
│  - API Endpoints     │
│  - Gemini Proxy      │
└──────────┬───────────┘
           │
┌──────────┴───────────┐
│  MongoDB Database    │
│  - Users & Context   │
│  - Chat History      │
│  - Memories          │
└──────────────────────┘
```

## Prerequisites

- Node.js 18+ and npm
- MongoDB (local or cloud instance like MongoDB Atlas)
- Google Gemini API key
- A Moodle instance with admin access (for testing)
- SSL certificate (required for production LTI)

## Step 1: Backend Setup

### 1.1 Install Dependencies

```bash
cd backend
npm install
```

### 1.2 Configure Environment Variables

Create a `.env` file in the `backend` directory:

```bash
cp .env.example .env
```

Edit `.env` with your values:

```env
# Server Configuration
PORT=3001
NODE_ENV=development
LOG_LEVEL=info

# LTI Configuration
LTI_KEY=your-random-secret-key-here  # Generate a strong random string
LTI_URL=http://localhost:3001         # In production: https://your-domain.com

# Database Configuration
MONGODB_URI=mongodb://localhost:27017/moodle-tutorbot

# AI Configuration
GEMINI_API_KEY=your-gemini-api-key-here

# CORS Configuration
CORS_ORIGIN=http://localhost:3000
```

**Important Notes:**
- `LTI_KEY`: Generate a secure random string (e.g., using `openssl rand -hex 32`)
- `LTI_URL`: Must be publicly accessible HTTPS URL in production
- `MONGODB_URI`: Use MongoDB Atlas for cloud hosting or local MongoDB

### 1.3 Start MongoDB

**Option A: Local MongoDB**
```bash
# Install MongoDB Community Edition
# macOS
brew tap mongodb/brew
brew install mongodb-community
brew services start mongodb-community

# Ubuntu/Debian
sudo apt-get install mongodb
sudo systemctl start mongodb
```

**Option B: MongoDB Atlas (Recommended for Production)**
1. Create account at https://www.mongodb.com/cloud/atlas
2. Create a free cluster
3. Get connection string and update `MONGODB_URI`

### 1.4 Run Backend Server

**Development:**
```bash
npm run dev
```

**Production:**
```bash
npm run build
npm start
```

The backend will run on `http://localhost:3001`

## Step 2: Frontend Setup

### 2.1 Configure Environment

Create `.env` in the root directory:

```bash
cp .env.example .env
```

Edit `.env`:

```env
VITE_API_URL=http://localhost:3001
```

### 2.2 Build Frontend

In production, the backend serves the frontend automatically:

```bash
# From root directory
npm install
npm run build
```

This creates a `dist/` folder that the backend will serve.

## Step 3: Register Tool in Moodle

### 3.1 Get Tool Configuration

Start your backend server and navigate to:
- JWKS Endpoint: `http://localhost:3001/lti/keys`
- Login Endpoint: `http://localhost:3001/lti/login`

### 3.2 Register in Moodle (Admin)

1. Go to **Site Administration → Plugins → Activity modules → External tool → Manage tools**

2. Click **Configure a tool manually**

3. Fill in the configuration:

   ```
   Tool name: Moodle Tutorbot
   Tool URL: http://localhost:3001/lti/launch
   LTI version: LTI 1.3
   Public key type: Keyset URL
   Public keyset: http://localhost:3001/lti/keys
   Initiate login URL: http://localhost:3001/lti/login
   Redirection URI(s): http://localhost:3001/lti/launch
   ```

4. **Tool configuration settings:**
   - Default launch container: New window
   - Privacy:
     - ✓ Share launcher's name with tool
     - ✓ Share launcher's email with tool
     - ✓ Accept grades from the tool

5. **Services:**
   - ✓ IMS LTI Assignment and Grade Services
   - ✓ IMS LTI Names and Role Provisioning

6. Click **Save changes**

### 3.3 Get Platform Configuration from Moodle

After registration, Moodle will provide:
- **Platform ID** (Moodle URL)
- **Client ID** (generated by Moodle)
- **Authentication request URL** (usually `/mod/lti/auth.php`)
- **Access token URL** (usually `/mod/lti/token.php`)

### 3.4 Register Moodle Platform in Your Backend

Add these to your backend `.env`:

```env
MOODLE_URL=https://your-moodle-instance.com
MOODLE_NAME=My Moodle Instance
MOODLE_CLIENT_ID=the-client-id-from-moodle
```

Restart the backend to register the platform automatically.

## Step 4: Add Tool to a Course

### 4.1 Add Activity

1. Go to a course
2. Turn editing on
3. Click **Add an activity or resource**
4. Select **External tool**
5. Configure:
   - **Activity name**: "AI Tutorbot"
   - **Preconfigured tool**: Select "Moodle Tutorbot"
   - **Privacy**: Ensure "Share launcher's name" and "Share launcher's email" are checked

6. Click **Save and display**

### 4.2 Launch the Tool

Click on the activity to launch the Tutorbot in a new window.

## Step 5: Production Deployment

### 5.1 Requirements

- **HTTPS**: LTI 1.3 requires HTTPS in production
- **Domain name**: A publicly accessible domain
- **SSL Certificate**: Use Let's Encrypt or a commercial certificate

### 5.2 Deployment Options

#### Option A: Heroku

```bash
# Install Heroku CLI
heroku create your-tutorbot-name

# Add MongoDB
heroku addons:create mongolab:sandbox

# Set environment variables
heroku config:set LTI_KEY=your-secret-key
heroku config:set GEMINI_API_KEY=your-api-key
heroku config:set LTI_URL=https://your-tutorbot-name.herokuapp.com
heroku config:set NODE_ENV=production

# Deploy
git push heroku main
```

#### Option B: DigitalOcean/AWS/GCP

1. Set up a VPS or cloud instance
2. Install Node.js, MongoDB, and PM2
3. Clone repository
4. Configure environment variables
5. Build frontend: `npm run build`
6. Start backend with PM2: `pm2 start backend/dist/server.js`
7. Configure Nginx as reverse proxy with SSL

#### Option C: Docker

```dockerfile
# Dockerfile
FROM node:18-alpine

WORKDIR /app

# Copy backend
COPY backend/package*.json ./backend/
RUN cd backend && npm install --production

# Copy frontend build
COPY dist ./dist

# Copy backend source
COPY backend/dist ./backend/dist

EXPOSE 3001

CMD ["node", "backend/dist/server.js"]
```

Build and run:
```bash
docker build -t moodle-tutorbot .
docker run -d -p 3001:3001 --env-file .env moodle-tutorbot
```

### 5.3 Update Moodle Configuration

After deployment, update your Moodle tool configuration with production URLs:
- Tool URL: `https://your-domain.com/lti/launch`
- Public keyset: `https://your-domain.com/lti/keys`
- Initiate login URL: `https://your-domain.com/lti/login`

## Testing

### Test LTI Launch

1. Launch tool from Moodle course
2. Verify user authentication (name should appear)
3. Add some memories and save
4. Send a chat message
5. Verify response is personalized based on memories
6. Close and reopen tool - data should persist

### Test Multiple Users

1. Launch as student A, add memories, chat
2. Launch as student B in the same course
3. Verify student B cannot see student A's data

### Test Multiple Courses

1. Launch in Course 1, add memories
2. Launch in Course 2
3. Verify memories are course-specific

## Troubleshooting

### "No valid LTI session found"

- Check that you launched from Moodle, not by direct URL
- Verify LTI configuration in Moodle
- Check backend logs for errors

### "Error loading data from backend"

- Verify backend is running
- Check MongoDB connection
- Check CORS settings match frontend URL

### LTI Launch Fails

- Verify HTTPS in production
- Check platform registration (MOODLE_CLIENT_ID matches Moodle)
- Verify JWT keys are properly configured
- Check Moodle logs: Site Administration → Reports → Logs

### Gemini API Errors

- Verify `GEMINI_API_KEY` is valid
- Check API quota limits
- Review backend logs for specific errors

## API Endpoints

For reference, the backend exposes:

### LTI Endpoints
- `POST /lti/login` - OIDC login initiation
- `POST /lti/launch` - LTI launch endpoint
- `GET /lti/keys` - JWKS public keys
- `POST /lti/register` - Dynamic registration

### API Endpoints (require LTI authentication)
- `POST /api/chat/message` - Send message (non-streaming)
- `POST /api/chat/stream` - Send message (streaming)
- `GET /api/chat/history` - Get chat history
- `DELETE /api/chat/history` - Clear chat history
- `GET /api/memories` - Get memories
- `POST /api/memories` - Create memory
- `PUT /api/memories/:id` - Update memory
- `DELETE /api/memories/:id` - Delete memory
- `PUT /api/memories/bulk` - Bulk update memories

## Security Considerations

1. **API Keys**: Never commit `.env` files to git
2. **LTI Key**: Use a strong random key for `LTI_KEY`
3. **HTTPS**: Always use HTTPS in production
4. **Database**: Secure MongoDB with authentication
5. **CORS**: Restrict `CORS_ORIGIN` to your domain
6. **Rate Limiting**: Consider adding rate limiting to API endpoints
7. **Session Security**: Configure secure session cookies in production
